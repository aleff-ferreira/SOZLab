## 0. Corrections and flags to your candidate list (read first)

1. **MDAnalysis `waterdynamics` is deprecated.** In the stable docs (2.11.0) the page `MDAnalysis.analysis.waterdynamics` is a stub: deprecated since 2.8.0 in favour of the MDAKit `waterdynamics`, to be removed in 3.0.0. The class documentation used below comes from the archived 2.7.0 docs and the MDAKit API page; both carry the same definition text.
2. **Which paper MDAnalysis cites for survival probability.** The docs cite Liu, Harder and Berne 2004 (J. Phys. Chem. B 108:6595) for SP. Rapaport 1983 is cited there for hydrogen-bond lifetimes. The parenthetical in your candidate 2 (time-origin-averaged survival or continuous-presence correlation functions) is not supported by the Rapaport abstract: UNVERIFIED. Rapaport's abstract only says that definitions of bond lifetime are discussed and compared.
3. **Rapaport title.** Crossref registers the title as *Hydrogen bonds in water*; the Taylor and Francis/OpenAlex title carries the subtitle *Network organization and lifetimes*. Same DOI, so cite by DOI.
4. **Laage and Hynes.** The 2006 Science paper is about reorientation, not residence times. The paper that critiques the Impey residence-time prescription is Laage and Hynes, J. Phys. Chem. B 2008, 112, 7697 (added below as 3b). Do not confuse it with J. Phys. Chem. B 2008, 112, 14230, which is a different reorientation paper.
5. **Titles corrected.** Nguyen 2012 is *Grid inhomogeneous solvation theory: hydration structure and thermodynamics of the miniature receptor cucurbit[7]uril*. Ramsey 2016 is *Solvation thermodynamic mapping of molecular surfaces in AmberTools: GIST*.
6. **Young 2007 and WaterMap.** The PNAS paper title and abstract do not name WaterMap (the abstract says a solvent analysis technique based on inhomogeneous solvation theory). I could not read the PNAS full text, so whether it uses the name is UNVERIFIED. The follow-up Abel et al. 2008 (J. Am. Chem. Soc.) contains zero occurrences of the string WaterMap in its text and cites Young 2007 as its reference 2.
7. **Grossfield et al. year.** PubMed gives 2018 (online 2018-10-27); Crossref gives an issue date of 2019. Your 2018 follows PubMed.
8. **Mark and Nilsson 2001** (J. Phys. Chem. A 105:9954) is an NVE study at fixed volume (per its abstract), so it does not deliver an equilibrium TIP3P density. I recommend not using it as the independent density compilation (see 2a for replacements). I could not open the full text to see which density was imposed: UNVERIFIED.
9. **TIP3P bulk density depends on the model variant and protocol.** The MDAnalysis docs list 1.002 g/cm3 (0.0335 per cubic angstrom) at 298 K; the cpptraj manual's GIST table gives 0.0329 per cubic angstrom (0.984 g/cm3) at 300 K; a 2021 coexistence benchmark gives 0.9839 and 0.978 g/cm3 at 300 K. The GIST default of 0.0334 matches none of them. See 2a.
10. **cpptraj HTML manual URL is dead.** `amber-md.github.io/cpptraj/CPPTRAJ.xhtml` returns a GitHub Pages 404. I used the manual source `doc/cpptraj.lyx` in the official repository.
11. **MDAnalysis 2.11.0 fixed missed neighbours in some triclinic boxes** in the grid neighbour search `FastNS` (documented as issue 4906). Record the MDAnalysis version in every output; results from older versions may differ in such boxes. See 2e.
12. **MDTraj has no function named `wrap`** in the 1.9.4 API. The documented periodic helpers are `Trajectory.image_molecules` and `Trajectory.make_molecules_whole`. Newer MDTraj docs were not reachable (`mdtraj.org/latest` returned AccessDenied).
13. **VMD docs.** `ks.uiuc.edu` and `tcbg.illinois.edu` fail TLS verification from this environment (curl and the fetch tool both rejected the certificate); I read Wayback copies. The periodic-aware selection keyword `pbwithin` appears only in VMD-L developer replies, not in the User's Guide pages I could read.
14. **Brooke 1996 page range.** 189 to 194 is second-hand (secondary sources quoting Brooke's own reference). Crossref lists the CRC Press reissue chapter with pages 207 to 212 under a different DOI.
15. **Hofer et al.** Crossref gives 2003 (online); the volume 25(2) print year is 2004.
16. **Numbers I could not confirm** are listed in section 5: Impey 1983 residence-time values, any Cl- first-shell residence time in classical water, the TIP3P density printed in the 1983 TIP3P paper.

### 15. MDAnalysis `SurvivalProbability`: definition, `intermittency`, references

URLs read: archived full docs `https://docs.mdanalysis.org/2.7.0/documentation_pages/analysis/waterdynamics.html`; MDAKit API `https://www.mdanalysis.org/waterdynamics/api.html`; stable stub `https://docs.mdanalysis.org/stable/documentation_pages/analysis/waterdynamics.html`; algorithm page `https://docs.mdanalysis.org/stable/documentation_pages/lib/correlations.html`.

- **Definition sentence** (MDAnalysis 2.7.0 docs, class `SurvivalProbability`; the sentence begins with the name Survival Probability (SP) and continues): "gives the probability for a group of particles to remain in a certain region".
- **Formula (paraphrased).** P(tau) is the average, over all time origins t, of N(t, t+tau) / N(t), where N(t) is the number of particles in the region at time t and N(t, t+tau) is the number present at every frame from t to t+tau. The 2.7.0 notes say the docs were aligned with the discrete autocorrelation function. `window_step` (called `step` in `run`) is advised to be at least `tau_max` so windows are independent; the default is 1.
- **`intermittency` parameter of `run()`.** The largest run of consecutive frames in which an atom may be outside the region while still being treated as present, provided it is back at the next frame. 0 means strict continuous survival. With intermittency 2, absences of up to two consecutive frames are forgiven. The tolerance is counted in frames, not in time units. Implementation in `lib.correlations.correct_intermittency`: gaps of at most k frames are filled before the autocorrelation is computed.
- **Other parameters.** `residues=True` analyses residues instead of atoms (one atom inside is enough); `stop` is exclusive; `tau_max` is the largest lag. Returns `tau_timeseries`, `sp_timeseries`, and `sp_timeseries_data` (raw per-window values).

### 16. Usability-method references

**16a. Nielsen's 10 usability heuristics.** Page *10 Usability Heuristics for User Interface Design*, Jakob Nielsen, `https://www.nngroup.com/articles/ten-usability-heuristics/`; shows publication 1994-04-24 and last review 2024-01-30. The ten titles, in order: Visibility of system status; Match between system and the real world; User control and freedom; Consistency and standards; Error prevention; Recognition rather than recall; Flexibility and efficiency of use; Aesthetic and minimalist design; Help users recognize, diagnose, and recover from errors; Help and documentation. What the page claims: they are broad rules of thumb, not specific usability guidelines; developed with Rolf Molich in 1990 and refined in 1994. References it lists (DOIs checked in Crossref): Nielsen and Molich, *Heuristic evaluation of user interfaces*, CHI '90, pp. 249-256, 10.1145/97243.97281; Nielsen, *Enhancing the explanatory power of usability heuristics*, CHI '94, pp. 152-158, 10.1145/191666.191729; Molich and Nielsen, Commun. ACM 33(3):338-348 (1990) and Nielsen's chapter *Heuristic evaluation* in *Usability Inspection Methods* (Wiley, 1994) are listed on the page but were not checked in a registry. Status: VERIFIED (page read through the fetch tool). What it does not give: a pass/fail checklist or an evidence-of-coverage claim; the page itself calls the list rules of thumb.

**16b. Nielsen and Landauer 1993.** *A mathematical model of the finding of usability problems*, Proc. ACM INTERCHI '93 (Amsterdam, 24-29 April 1993), pp. 206-213, DOI [10.1145/169059.169166](https://doi.org/10.1145/169059.169166) (Crossref lists the container as the CHI '93 proceedings). Status: VERIFIED (Crossref, OpenAlex abstract, and the reference entry on the NN/g article below).

- What the paper does (abstract): across 11 studies, problem detection versus the number of users tested or heuristic evaluators used is well modelled as a Poisson process; the model can plan the amount of evaluation for a desired thoroughness, estimate problems remaining from early results, and, given evaluation costs and detection values, estimate the number of evaluations that maximises benefit to cost. For its worked medium example it reports that 16 evaluations would be worth their cost with the best benefit-to-cost ratio at four.
- Later NN/g article *Why You Only Need to Test with 5 Users* (Nielsen, 2000-03-18, `https://www.nngroup.com/articles/why-you-only-need-to-test-with-5-users/`): states the model as N(1 - (1 - L)^n), with N the total number of problems in the design, L the proportion found by a single user, a typical L of 31 percent averaged over the projects the authors studied, and about 85 percent found by five users. The formula is an image on that page; the symbolic form here follows the page's text description (symbolic form UNVERIFIED beyond that description).
- **What it justifies:** a planning heuristic that detection has diminishing returns in the number of independent evaluators, and a way to reason about how many to recruit under stated assumptions. This is the only use you plan to make of it.
- **What it does not justify** (each point with its basis):
  1. Anything about a specific product: the fit is across 11 published studies (abstract) and the 31 percent is an average over projects (NN/g). Detection probability varies by product, task set, evaluator and problem, whereas the simple model uses one L. Faulkner 2003 (Behav. Res. Methods Instrum. Comput. 35(3):379-383, 10.3758/bf03195514, PMID 14587545, PubMed abstract) tested 60 users and drew random sets of five: some sets found 99 percent of problems and others only 55 percent; with 10 users the worst set found 80 percent and with 20 users 95 percent.
  2. That the problems found are real, important, or fixed: it counts discoveries.
  3. Applicability to a scripted check. A deterministic script is not a sample of independent evaluators; each problem it can detect is found on every run and each it cannot detect is never found, so the independence and common-detection-probability assumptions fail. This point is my inference, not a source statement.
  4. NN/g's own later caveats (article *How Many Test Users in a Usability Study?*, 2012-06-03, `https://www.nngroup.com/articles/how-many-test-users/`): quantitative studies need about 20 users, card sorting about 15 per group, and several distinct user groups need roughly five per group.
- Suggested wording consistent with the evidence: cited for the idea that the number of evaluators in a problem-discovery study can be planned with a diminishing-returns model; no claim is made about what share of SOZLab's problems any number of evaluators would find.

**16c. System Usability Scale.** Brooke J. *SUS: a quick and dirty usability scale*. In: Jordan PW, Thomas B, Weerdmeester BA, McClelland AL (eds). *Usability Evaluation in Industry*. London: Taylor and Francis; 1996. Pages: 189-194 per secondary sources (SECONDARY; Brooke's own 2013 reference list omits pages; Crossref's CRC Press reissue entry, DOI 10.1201/9781498710411-35, lists pp. 207-212). Primary account read: Brooke J. *SUS: a retrospective*. J. Usability Studies 2013;8(2):29-40 (archived journal page, `https://web.archive.org/web/2023/https://uxpajournal.org/sus-a-retrospective/`). Confirmed there: 10 statements chosen from a pool of 50, half positively and half negatively worded, each item contributing 0 to 4 points, summed and multiplied by 2.5 to give 0 to 100; meant as a quick measure of perceived usability. Stated limits: it is not diagnostic (it does not say what makes a system usable or not); scores of 0 to 100 are not percentages (percentile rank needs normative data); correlation with task performance is modest; quick and dirty describes its use, not how it was built. Does not justify: usability-problem discovery counts, or any claim about task success. It needs human respondents, so a scripted check cannot produce a SUS score.

**16d. Shneiderman 1996.** *The eyes have it: a task by data type taxonomy for information visualizations*. Proc. 1996 IEEE Symposium on Visual Languages, pp. 336-343, DOI [10.1109/VL.1996.545307](https://doi.org/10.1109/VL.1996.545307). VERIFIED (registry plus OpenAlex abstract; Crossref lacks an issued date and OpenAlex shows 2002, the digital-record year; the proceedings title carries 1996). The abstract presents the Visual Information-Seeking Mantra (overview first, then zoom and filter, then details on demand) as a useful starting point, and offers a taxonomy of seven data types (1-D, 2-D, 3-D, temporal, multi-dimensional, tree, network) and seven tasks (overview, zoom, filter, details-on-demand, relate, history, extract). It is a design principle and taxonomy, not an empirically validated rule; the abstract itself frames the mantra as only a starting point. The UMD-hosted PDF is a scanned image with no text layer, so only the abstract was checked.

## 2. Published reference numbers

### (a) TIP3P liquid water, number and mass density near 298 to 300 K and 1 atm

Conversion used throughout: number density n [per cubic angstrom] = rho [g/cm3] x N_A [1/mol] / M [g/mol] x 10^-24 (one cm3 is 10^24 cubic angstrom), with N_A = 6.02214076e23 per mol and M = 18.01528 g/mol unless the source states another M. Inverse: rho = n x M / (N_A x 10^-24).

### (c) Bulk reference density and grid definitions: GIST (cpptraj) and MDAnalysis `DensityAnalysis`

**GIST, cpptraj manual** (`https://github.com/Amber-MD/cpptraj/blob/master/doc/cpptraj.lyx`, section gist; read at the commit noted above):

- `refdens <rdval>`: the bulk-water reference density behind g_O, g_H and the translational entropy; **default 0.0334 molecules per cubic angstrom**. The manual says the default is taken as the experimental number density of pure water at 300 K and 1 atm, that water models differ slightly under those conditions, and that if the model's bulk density at the simulation T and P deviates significantly from 0.0334 the actual value should be supplied with `refdens`.
- Grid: a user-specified three-dimensional rectangular grid of cubic voxels. `gridcntr <x y z>` gives the centre in angstrom (default 0 0 0); `griddim <nx ny nz>` the number of voxels per axis (default 40 40 40); `gridspacn` the voxel edge (default 0.5 angstrom; values above 0.75 not recommended). `rmsfit <fitmask>` makes the grid follow the atoms of the mask, centred and rotated. `neighborcut` default 3.5 angstrom (solvent O-O neighbours). The manual warns that smaller voxels need longer sampling to converge.
- Counting rule: a water is counted in a voxel if its oxygen coordinates are inside the voxel. Output g_O is the oxygen number density in units of the bulk density (the expectation for neat water is 1).
- Manual recommendations: restrain the solute to essentially one conformation; everything that is not water is treated as solute, so strip counterions and cosolutes first; for a 0.5 angstrom grid at room temperature run at least 10 to 20 ns and check convergence by processing increasing numbers of frames. `noimage` only disables imaging in the energy calculation.
- Related `grid` action: `normdensity [density <d>]` divides each bin by (frames x bin volume x density), with the default water density taken from 1.0 g/mL; `rmsfit <mask>` rotates the grid to follow a fit mask; `boxref` is the only documented way to set up a non-orthogonal grid.

**MDAnalysis `DensityAnalysis`** (`https://docs.mdanalysis.org/stable/documentation_pages/analysis/density.html`, version 2.11.0):

- Grid definition: `delta` is the bin size in angstrom (same in x, y, z; default 1.0). `padding` (default 2.0 angstrom) enlarges the histogram beyond the initial box and is ignored for a user grid. `gridcenter` (3-vector, angstrom) with `xdim`, `ydim`, `zdim` (angstrom) defines a user grid; if omitted a grid is generated from the atoms of the group. The user must make sure a user grid encloses the selected atoms on every frame. `UpdatingAtomGroup` selections are supported (for example water oxygens within a cutoff of a solute).
- Units: the result `results.density` is a physical density in inverse cubic angstrom, not raw counts. `convert_density('TIP4P')` (or `'TIP3P'`, `'SPC'`, `'water'`) re-expresses it relative to the stored bulk value of that model at standard conditions (`MDAnalysis.units.water`). Counts per voxel are recovered by converting to `A^{-3}` and multiplying by the voxel volume (the docs give this recipe); a probability density is the grid divided by its sum.
- Explicit warnings (paraphrased): the density is computed in the fixed coordinate system of the unit cell, so the protein has to be positioned and held fixed relative to the box axes. The input trajectory must be centred on the protein, have all molecules made whole across periodic boundaries, have solvent remapped so that it is closest to the solute (stated as important for triclinic cells such as a dodecahedron or truncated octahedron), and have a fixed frame of reference, for example from superposition on a reference. The docs' own example trajectory omits these steps and says so.

### (d) GROMACS: dynamic selections, PBC and trjconv ordering

Pages: `https://manual.gromacs.org/current/onlinehelp/gmx-select.html`, `.../selections.html`, `.../gmx-trjconv.html`, `.../gmx-spatial.html` (documentation header reads GROMACS 2026.4).

- **`gmx select`:** dynamic selections are re-evaluated every frame. The keyword `within <r> of <positions>` selects atoms within distance r (nm) of the given positions; related keywords are `distance`, `mindistance`, `insolidangle` and `same <keyword> as`; selections combine with and, or, not. Reference positions can be atoms or residue or molecule centres, with prefixes `whole_`, `part_` and `dyn_` (which control which atoms define a centre for partly selected molecules). `-[no]pbc` (default on) applies periodic boundary conditions to distances; `-[no]rmpbc` (default on) makes molecules whole each frame. Outputs: `-os` number of positions per frame; `-oc` covered fraction; `-oi` and `-on` selected items per frame (index file with one group per frame for dynamic selections); `-om` per-frame 0/1 mask for the first selection; `-of` occupancy fraction (share of frames in which each position is selected); `-ofpdb` that occupancy in a PDB; `-olt` histogram of the time positions were continuously selected, with `-cumlt` controlling whether sub-intervals count.
- **Surface selections:** no selection keyword named surface appears in the selection documentation I fetched. Surface areas are a separate tool (`gmx sasa`, not read).
- **`gmx trjconv` `-pbc` options:** `mol` puts molecule centres of mass in the box (needs a run input file); `res` and `atom` likewise for residues and atoms; `nojump` undoes jumps across the box so molecules stay whole if they began whole, giving a continuous trajectory in which molecules may diffuse out of the box; `cluster` clusters the selected group around its centre of mass; `whole` only repairs broken molecules. `-ur rect|tric|compact` sets the unit-cell representation (differs only for triclinic boxes); `-center` centres a group; `-boxcenter tric|rect|zero` sets the centre; combining `-pbc mol` with `-center` puts all molecules in the box after centring. `-fit rot+trans` superposes frames on a reference. The trjconv help says not every combination of `-pbc`, `-fit`, `-ur` and `-center` can be done in one call and advises multiple calls.
- **Official ordering for solvent-density work:** the only explicit multi-step recipe in the official docs is in `gmx spatial` (a solvent spatial distribution function written as a cube file): step 1, `trjconv` with `-boxcenter tric -ur compact -pbc none` to centre; step 2, `trjconv` with `-fit rot+trans` on the output of step 1; step 3, run `gmx spatial` on the fitted trajectory; for micelle-like systems add `trjconv -pbc cluster` between steps 1 and 2. Its warning: after `-fit rot+trans` the system rotates and translates in space, so the returned values are valid only in the region around the central group that overlaps the system volume throughout the whole rotated and translated trajectory; the user must ensure that. I found no other official statement of a recommended `-pbc mol` / `nojump` / `-center` / `-fit` order; a recipe beyond the `gmx spatial` one is UNVERIFIED as official guidance.

### (e) Minimum-image convention: when it is valid

- **GROMACS reference manual** (`https://manual.gromacs.org/current/reference-manual/algorithms/periodic-boundary-conditions.html`, section Cut-off restrictions): the minimum image convention means the cut-off used to truncate non-bonded interactions must stay below half the shortest box vector, R_c < (1/2) min(|a|, |b|, |c|); beyond that, two images of one particle could both lie inside the cut-off. For macromolecules in solution the length of each box vector must also exceed the macromolecule's extent along that edge plus twice the cut-off so that a solvent molecule cannot see both sides of the solute (the manual notes it is common to compromise on this). Triclinic generalisation as documented: box vectors in the reduced form a_y = a_z = b_z = 0, a_x, b_y, c_z > 0, |b_x| <= a_x/2, |c_x| <= a_x/2, |c_y| <= b_y/2; for efficiency GROMACS restricts the cut-off more for triclinic boxes: R_c < min(a_x, b_y, c_z) for grid search and R_c < (1/2) min(a_x, b_y, c_z) for simple search. These restrictions are stated for the non-bonded cut-off of the MD engine; they are the documented form of the rule, not a rule written specifically for analysis zones.
- **MDAnalysis docs:** distance functions (`distance_array`, `capped_distance` and others) apply the minimum image convention when a box is passed, for orthogonal or triclinic boxes (`https://docs.mdanalysis.org/stable/documentation_pages/lib/distances.html`). Geometric selections (`around`, `sphzone` and so on) take periodicity into account by default and the `periodic` keyword of `select_atoms` controls this (`.../selections.html`). The grid neighbour search `FastNS` is documented as using the minimum image convention; the 2.11.0 change note says it fixed missed neighbours in triclinic boxes where both the x component of the second box vector and the y component of the third are non-zero, or more than one angle is not 90 degrees (issue 4906, labelled defect and PBC, closed 2026-10-19) (`.../lib/nsgrid.html`). The docs do not state the half-box condition for selections; I found no MDAnalysis page that does.
- **Textbooks:** Allen MP, Tildesley DJ, *Computer Simulation of Liquids*, 2nd ed., Oxford University Press 2017 (DOI 10.1093/oso/9780198803195.001.0001) and Frenkel D, Smit B, *Understanding Molecular Simulation*, 2nd ed., Academic Press/Elsevier 2002 (DOI 10.1016/B978-0-12-267351-1.X5000-7) are the standard references for the minimum-image convention. Bibliographic records VERIFIED in Crossref; I did not open either book, so section and page numbers for the cut-off-below-half-box statement are UNVERIFIED.

## 4. Pitfalls documented in the literature

**(i) Bias of mean residence time from window-edge (censored) events and from short flickering events**

- Flickering and recrossing: Impey et al. introduced the tolerance time t* for this purpose. Laage and Hynes 2008 (PMID 18510295, abstract) report that the resulting residence time is very sensitive to t* and that the conventional 2 ps can seriously overestimate residence times for low-barrier exchanges; they propose the stable-states picture. Joung and Cheatham 2009 (PMC2755304) restate this and use a stable-states-based definition. Sanchez 2022 (J. Phys. Chem. B 126(43):8804-8812, 10.1021/acs.jpcb.2c03756, PMID 36269165; abstract) gives estimators for residence-time distributions, mean residence times and their uncertainties, and notes that methods which discard short escapes need a maximum escape duration as a parameter; he offers a parameter-free alternative for the mean residence time. A follow-up on uncertainty of mean residual times is Sanchez and Garcia, Commun. Nonlinear Sci. Numer. Simul. 2024;136:108111, 10.1016/j.cnsns.2024.108111 (registry only; includes an aqueous NaCl example per its abstract in the search index).
- Definition dependence: Rapaport 1983 (abstract) discusses the difficulty of defining a meaningful lifetime and compares definitions.
- Censoring: Kaplan and Meier 1958 is the standard treatment of observations whose event time is cut off. In a finite trajectory, residence events already in progress at the first frame or still in progress at the last frame are censored. I did not find an MD-specific paper I could read that quantifies this window-edge bias, and I could not confirm from the abstracts that Sanchez 2022 or 2024 treat edge events: UNVERIFIED.

**(ii) Dependence on the trajectory output interval**

- Documentation fact: in MDAnalysis the gap tolerance (`intermittency`), the origin spacing (`step`) and the largest lag (`tau_max`) are all counted in frames, so the physical tolerance is frames times the output interval; the docs say `step` and `tau_max` work consistently with intermittency.
- A published protocol example: Mamatkulov and Schwierz 2018 stored frames every 0.2 ps (with a 2 fs time step) for residence-time statistics.
- I found no peer-reviewed source that quantifies how residence times or lifetimes change with output interval: UNVERIFIED. Inference, not sourced: if the output interval approaches or exceeds t*, recrossing events shorter than the interval cannot be resolved, and any tolerance expressed in frames changes meaning when the interval changes. Report the interval beside every residence time.
- Tangential official note: the GROMACS trjconv help says `gmx filter` can reduce the number of frames with low-pass filtering to reduce aliasing of high-frequency motion when thinning trajectories for movies.

**(iii) Density-map artefacts from an unaligned solute or inconsistently wrapped solvent**

- MDAnalysis docs: the density is computed in the fixed unit-cell frame, so the trajectory must be centred, molecules made whole, solvent remapped to the closest image of the solute (important for triclinic cells), and the solute superposed on a reference (see 2c).
- cpptraj docs: GIST expects a solute restrained to essentially one conformation, treats all non-water as solute, and offers `rmsfit` for a grid that follows the solute; finer voxels converge more slowly.
- GROMACS docs: `gmx spatial` warns that after `-fit rot+trans` the values are valid only in the region that stays inside the periodic system over the whole rotated and translated trajectory; `trjconv -pbc nojump` keeps molecules whole but lets them diffuse out of the box.
- VMD docs (volmap ils command only): a requested grid that exceeds the periodic box leaves ill-defined regions and a warning is printed; wrapping so the grid sits in the box centre is advised.
- Published practice: Abel et al. 2008 restrained protein heavy atoms (1000 kJ/mol/nm2) and analysed solvent in the solute frame.
- Related peer-reviewed item: Bruininks BMH et al., *Unbreaking assemblies in molecular simulations with periodic boundaries*, J. Chem. Inf. Model. 2023;63(11):3448-3452, 10.1021/acs.jcim.2c01574, PMID 37171034 (PubMed record checked): molecules and assemblies split across periodic boundaries make analysis and visualisation difficult, which is the failure mode for any per-voxel count taken without making solutes whole first.
